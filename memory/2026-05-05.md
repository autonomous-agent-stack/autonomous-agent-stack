## Control Plane v2 operator actions

- 中文：新增 `ControlPlaneOperatorActionRequest`，并为 v2 task/run 提供 cancel、retry、force-fail API；404/409 语义按目标缺失与状态不允许区分。
- English: Added `ControlPlaneOperatorActionRequest` and v2 task/run cancel, retry, and force-fail APIs; 404 and 409 distinguish missing targets from state-incompatible operations.
- 中文：v2 cancel 仅允许 queued/running worker run；queued 直接同步为 `cancelled`，running 写入 worker metadata `cancel_requested` 并记录 `run.cancel_requested`，等待 worker terminal report 再投影终态。
- English: v2 cancel is limited to queued/running worker runs; queued runs sync directly to `cancelled`, while running runs write `cancel_requested` to worker metadata and record `run.cancel_requested`, then wait for the worker terminal report before terminal projection.
- 中文：v2 retry 只允许当前 `failed`/`cancelled` run，创建新的 worker run 与 v2 run，保留同一 task，并写入 `retry_of_run_id`、`retry_of_worker_run_id`、`retry_sequence`、`previous_run_ids` 与 `latest_retry_of_run_id` lineage。
- English: v2 retry is limited to the current `failed`/`cancelled` run, creates a new worker run and v2 run for the same task, and records lineage through `retry_of_run_id`, `retry_of_worker_run_id`, `retry_sequence`, `previous_run_ids`, and `latest_retry_of_run_id`.
- 中文：Telegram `/cancel` 与 `/retry` 现在优先解析 v2 `task_id`/`run_id`，非 v2 worker run 继续走旧 fallback；新增 owner-only `/force-fail`，仅作用于 v2 task/run。
- English: Telegram `/cancel` and `/retry` now resolve v2 `task_id`/`run_id` first while preserving legacy fallback for non-v2 worker runs; added owner-only `/force-fail` for v2 task/run targets only.
